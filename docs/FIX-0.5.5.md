# v0.5.5：切换账号启动 App 的瞬态失败

## 已定位的问题

现场切换账号失败：

```text
切换失败：启动桌面 App 失败：_LSOpenURLsWithCompletionHandler() failed with error -600。
回滚：已恢复切换前的 auth.json；已恢复切换前的 state.json；已重新启动 ChatGPT App
```

`-600` 是 macOS 的 `procNotFound`（AESend 找不到可投递的进程），不是“应用不存在”或签名错误。退出 ChatGPT 后立即调用 `open` 时，可能仍在两个窗口内：

- LaunchServices 尚未完成旧实例注销；
- 新实例已被拉起，但还没有开始处理打开事件。

`open` 在这两个窗口内会返回 `-600`，但应用往往已经启动或稍后启动成功。本次现场记录显示：失败发生在 `17:36:14`（本地时间，journal 记录为 `09:36:14Z`），回滚记录显示同一次重新启动成功；约 40 秒后同一账号切换也正常完成。另行用临时 AppKit 应用观察到 `open` 返回 `-600`、进程随后正常运行的行为，未启停 ChatGPT；该临时应用未纳入仓库。

原实现的两个问题：

1. `quit_desktop` 只等待进程从 `ps` 消失，没有等待 LaunchServices 释放注册，紧接着的 `open` 可能命中清理窗口。
2. `launch_desktop` 把单次 `open` 失败当作最终失败，直接触发回滚；回滚路径也没有处理“`open` 报错但实例已经启动”以及退出失败时的安全收尾。

## 修复行为

- 正常退出、信号退出和强制结束之后，最多等待 2 秒让 LaunchServices 释放旧注册；等待超时不会把成功退出改判为失败。
- 两次 `open` 结果中任一为 `-600` / `procNotFound` 时重试启动，间隔 0.3、0.8、1.5 秒；两次都不是瞬态错误才立即失败，不掩盖真实问题。
- 重试期间如果出现新的桌面主进程，视为启动成功；仅凭过期的 LaunchServices 注册不判定成功。`open` 返回 0 仍按启动请求成功处理，随后由 app-server 就绪检查兜底。
- 重试耗尽后再等待 1 秒确认新进程，避免把已经启动的 App 误判为失败。
- 回滚增加 `launch_attempted` 状态：先停止可能已用目标凭据启动的 App，再恢复 `auth.json` 和 `state.json`；若 App 无法退出，则中止恢复并保留备份，避免在 App 仍写入认证时覆盖旧凭据；只有原 App 已被退出时才重新启动，避免在 App 仍在运行时误报“已重新启动”。

## 验证与边界

- 新增 21 项回归测试（`tests/test_platform.py` 16 项、`tests/test_switch.py` 5 项）：`-600` 重试与退避、混合错误、非法错误码排除、新旧主进程判定、最终等待、路径回退、非瞬态错误不重试、LaunchServices 等待/超时/仅注册状态、启动模式/权限保护，以及回滚停止实例、退出失败中止恢复、退出成功后重启。
- 完整 257 项 Python 测试、963 项四语言文案生成与审查、14 项 Swift 测试通过；Swift 仅同步版本回退值，未改业务逻辑。
- 使用临时 AppKit 应用复现了 `-600` 的瞬态窗口，但**没有在真实账号上执行切号或重启 ChatGPT**；2 秒等待与 3.6 秒重试预算（单次 `open`/`lsappinfo` 超时另计）没有在真实 ChatGPT 上做时序标定。
- 如果 LaunchServices 长时间不释放且 `open` 持续返回 `-600`，仍会按原设计失败并回滚，不会无限重试。
- 仅验证 Apple Silicon 当前开发机；其他 macOS 版本和架构没有实机验收。
