# v0.5.3：运行检测与手动强制切换

## 已定位的问题

v0.5.2 把历史数据库 `thread_turns.status=inProgress` 当作永久有效的运行凭据。现场发现一条 24 天前的记录：没有桌面所有者、rollout 已不存在，仍阻止普通切换和自动接力。通过只读 IPC 与文件/进程时间核对复现，未修改用户数据库或重启 ChatGPT。

## 修复行为

- 优先使用桌面实时运行状态；终止轮次即使守护策略不允许自动续跑，也不会被误判为仍在执行。
- 只有桌面明确回复没有所有者，且轮次早于当前所有桌面主进程启动、rollout 也未在本次启动后更新时，才排除为历史残留。数据库和聊天文件保持原样。
- 网络/IPC 超时、协议失败、未知进程启动时间、本次启动后仍有更新，均保留为待核实。长时间安静运行不会仅因时间过长被排除。
- 同一聊天多条未完成历史记录合并检查，展示当前轮次 ID。
- 切换确认页提供运行检测、重新检测及逐次“我确认没有正在进行的聊天，强制切换”。选项只跳过本次活动轮次拦截；不启用强制杀进程，不跳过账号校验、备份、其他写入进程及本机额度守护检查。
- 新增只读 `activity --json`，包含 `active` 的判定来源和 `ignored_history` 的排除理由。手动 CLI 对应 `switch <alias> --desktop --confirm-idle --allow-chatgpt-restart`。
- 手动原聊天续跑可使用上述逐次确认；自动接力没有此选项，仍需确认中断指定聊天并重新检查其他聊天。
- 自动接力被阻止时提供具体聊天及原因，移除 GUI 中没有对应按钮的 `--force` 提示。诊断不再截去多行错误的开头。
- 四语言文案与可滚动确认页同步更新。

## 验证与边界

- 236 项 Python 测试、14 项 Swift 测试通过；四语言共 963 项文案，硬编码/未使用审查均为零。
- 隔离集成测试保留旧的残留行和原聊天活动行，执行真实状态判定、原轮次中断确认、临时凭据切换、原聊天提示词发送与新轮次回执；桌面和认证均使用夹具。
- 本机只读验证：报告中的旧记录被排除，当前两个实际执行的聊天仍被识别；未把所有任务判为空闲。
- 冻结后端和最终 Release 资产须执行扩展后的 `tools/smoke_bundle.py`：真实 Unix socket、明确无所有者响应、伪桌面进程启动时间、持久旧数据库、活动轮次拦截及中断后的空闲状态，外加后台启动/停止。该夹具不使用真实凭据或发送真实聊天消息。
- 没有在用户账号上执行真实切号、重启、中断或续跑，不能把夹具通过视作真实业务聊天验收。
