## 已处理的发现

| 范围 | 问题与修复 |
|---|---|
| 聊天定位 | 账号页按创建账号筛选、只列前 12 条；改为完整本机聊天，不把创建账号当作聊天所有权。主列表去掉 100 条截断，守护官方列表按游标分页，游标循环显式报错。 |
| 聊天选择 | 自动使用“最近聊天”，可能选错任务；自动接力必须指定完整 UUID，手动确认可明确选聊天或仅切号。 |
| 自动续跑 | 旧路径启动 `codex exec resume`，没有证明桌面原聊天继续；改用原聊天 IPC，保留原轮次/执行设置指纹，匹配新轮次回执才记成功。 |
| 手动切号 | 以前只打开深链接；确认页新增“切号后继续原聊天”及提示词，和自动接力共用原聊天链路。切号成功但发送失败分别展示。 |
| 运行中任务 | 自动接力确认指定轮次中断后才切号；其他任务仍执行时阻止切号。不自动重启已完成、用户主动停止或等待审批/输入的任务。 |
| 等待状态 | 安静数分钟的推理不等于空闲；旧数据库 inProgress 行可由桌面实时状态核对，不再只凭 mtime 推断可以重启。活动行查询移除前 20 条截断。 |
| 回执 | 中断/续跑前持久化操作意图；断线、崩溃或回执不明时不自动重发。切号后允许只读等待原聊天加载，发送本身不重试。 |
| 多语言确认页 | 显式使用当前选择的语言，sheet 继承 locale，规范化 `zh_Hant` 等标识，静态按钮及摘要不依赖系统语言。四语言离屏截图核对。 |
| 错误展示 | progress JSON 被过滤后没有人类错误时仍回退到原 JSON；改为简短失败提示。自动命令没有 stdout 时显示真实 stderr，而不是误报 JSON 解码失败。 |
| 同步失败 | 活动账号 HTTP 失败后状态仍可能是 ok；现在记录 error 和 last_error，界面保留失败详情，不把网络失败报告为同步成功。 |
| 并发写入 | CLI 未使用已有锁；账号写操作在读取状态前取得锁并重新加载。只读缓存不等待网络刷新；长期守护按单轮取得锁，不长期持锁。 |
| Token 所有权 | 强制刷新可能绕过活动 App 的 token 所有权；活动 Codex 运行期间始终使用只读 HTTP，不抢用旋转 refresh token。 |
| 额度解释 | 优先 Codex 的按 limit ID 数据，不使用其他模型桶兜底。缺失、NaN、越界或过期额度不能被当作 0% 已用来选择账号。服务明确拒绝时不发送。 |
| 自动配置 | 校验有限数值、百分比、正间隔、UUID 和布尔类型。单字段更新保留间隔、策略及未知字段；Python 使用唯一临时文件并原子写入。 |
